## 왜 필요한가

분석 결과 조회와 조항 상세 조회 화면에 계약서 쪽 값(주인, 제목, 쪽 수, 비슷한 계약서 등)이 필요합니다.
아직 이 값을 주는 메서드가 없어서, 지금은 분석 쪽 클래스가 계약서 테이블을 **읽기 전용 SQL로 직접** 읽고 있습니다.

- 임시 클래스: src/main/java/com/team/docai/domain/analysis/service/query/ContractReadOnlyQuery.java
- 아래 메서드가 생기면 분석 쪽이 이 클래스를 지우고 메서드 호출로 바꿉니다.
- 그 전까지 contract, contract_version, contract_page, document_type, schedule 테이블의 칼럼 이름이나 구조를 바꾸면 분석 쪽이 깨질 수 있으니 미리 알려 주세요.

## 1. ContractService.getVersionOwner

```java
// domain/contract/dto/ContractVersionInfo.java
public record ContractVersionInfo(
        Long contractId,
        int versionNo,      // contract_version.version_no
        int pageCount,      // 그 버전의 contract_page 행 수
        String title,       // contract.title (분석 전이면 null)
        int maskedCount     // 그 버전 contract_page.masked_count 합계
) { }

// domain/contract/service/ContractService.java
public ContractVersionInfo getVersionOwner(UUID userId, Long versionId)
```

동작
1. contract_version을 versionId로 찾는다. 없으면 CONTRACT_NOT_FOUND.
2. 그 버전의 contract를 찾는다. contract.user_id가 userId가 아니거나 deleted_at이 있으면 CONTRACT_NOT_FOUND.
3. pageCount, maskedCount는 ContractPageRepository.findByVersionIdOrderByPageNoAsc(versionId) 결과로 계산.
4. 읽기만 함: 클래스의 @Transactional(readOnly = true)를 그대로 따름. 잠금 없음.

쓰는 곳 (분석 쪽)
- 분석 결과 조회, 조항 상세 조회의 권한 확인: 분석에는 version_id만 있어서 주인을 알려면 필요
- 결과 화면의 버전 번호, 제목, 쪽 수, 가린 곳 수
- 멈춘 분석의 실패 알림 대상(userId) 찾기, AnalysisService.getRef 권한 확인

테스트
- 내 버전: 값이 맞게 나옴 (쪽 2장, masked_count 1과 2 → pageCount 2, maskedCount 3)
- 남의 버전, 없는 버전, 삭제된 계약서의 버전: CONTRACT_NOT_FOUND

## 3. ContractService.getSimilarContractInfo

```java
// domain/contract/dto/SimilarContractInfo.java
public record SimilarContractInfo(
        Long contractId,
        String title,
        OffsetDateTime analyzedAt,   // 그 계약서 최신 버전의 latest_analysis_id 분석의 completed_at
        int scheduleCount            // 그 계약서의 schedule 행 수 (삭제 안 된 것)
) { }

// domain/contract/service/ContractService.java
public Optional<SimilarContractInfo> getSimilarContractInfo(UUID userId, Long contractId)
```

동작
1. contract가 userId 것이고, archived = true이고, deleted_at이 없을 때만 값을 반환. 아니면 Optional.empty() (예외 아님).
2. analyzedAt: 최신 버전(current_version_no)의 latest_analysis_id가 가리키는 분석의 완료 시각.
   - 분석 테이블은 분석 담당 소유라 직접 읽지 말고, 분석 쪽 메서드가 필요하면 null로 두고 알려 주세요. 분석 쪽이 AnalysisService에 완료 시각을 주는 메서드를 추가하겠습니다.
3. scheduleCount: ScheduleRepository로 그 계약서의 일정 수.

쓰는 곳: 결과 화면의 "예전에 보관한 비슷한 계약서" 카드. 일정 수는 schedule 테이블이라 서비스 쪽에서만 셀 수 있습니다.

테스트: 보관된 내 계약서 → 값 있음 / 보관 안 됨, 남의 것, 삭제됨 → empty

## 4. NotificationService.createAnalysisResult 구현

지금 빈 껍데기라 분석 완료·실패 알림이 저장되지 않습니다. 시그니처는 그대로 둡니다.

```java
@Transactional
public void createAnalysisResult(UUID userId, Long analysisId, String type, String title, String subTitle)
// type: "ANALYSIS_DONE" 또는 "ANALYSIS_FAILED"
```

동작
- notification에 1행 저장 (user_id, analysis_id, type, title, sub_title). 칼럼 이름은 V2 마이그레이션의 notification 테이블을 따름.
- 같은 분석·같은 type은 한 번만 저장 (이미 있으면 아무것도 안 함).
- 분석 쪽은 상태가 바뀌는 같은 트랜잭션 안에서 이 메서드를 부릅니다. 여기서 예외가 나면 분석 상태 변경도 롤백되니, 중복은 예외 대신 건너뛰기로 처리해 주세요.

테스트
- 한 번 부르면 1행 생김
- 같은 분석·같은 type으로 두 번 부르면 여전히 1행
- 지금 ContractIntegrationTest 마지막 부분에 "알림 행을 만들지 않는다"는 확인이 있으면, 구현 후 그 확인을 바꿔야 합니다.
